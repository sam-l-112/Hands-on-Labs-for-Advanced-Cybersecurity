## 一、執行摘要

本次針對 Pack2TheRoot 實驗環境進行本機提權測試，確認 CVE-2026-41651 可讓無特權本地使用者透過 PackageKit 的 TOCTOU 漏洞取得 root 存取。過度寬鬆的 polkit 授權規則（`allow_active = yes`）與缺乏 state guard 的交易邏輯，是本次成功提權的兩大根本原因。此外，透過 `threading.Lock()` 實作的安全版本成功將 race condition 發生次數由 993 次降為 0 次，驗證了 TOCTOU 防禦的有效性。整體風險等級為 **高（High）**。

## 三、漏洞發現

### 3.1 過度寬鬆的 polkit 授權規則

| 欄位 | 內容 |
|------|------|
| **發現方式** | `pkaction --verbose` 輸出 |
| **受影響 action** | `org.freedesktop.packagekit.package-install-untrusted` |
| **問題設定** | `allow_active = yes`（應為 `auth_admin`）|
| **風險等級** | 高（High）|

**漏洞描述**

`allow_active = yes` 代表任何本地使用者在不需任何認證的情況下，即可觸發該 action。正常安全設定應為 `auth_admin`（需管理員密碼）。此過度寬鬆的授權規則是 Pack2TheRoot 能成功提權的**前提條件**——沒有這個設定，`pkcon install-local --allow-untrusted` 在執行前就會被 polkit 擋下。

攻擊者只需擁有本地 shell 帳號（無須密碼、無須 sudo），即可透過此設定繞過權限控管，直接觸發 PackageKit 的套件安裝功能。

**重現步驟**
1. `ssh labuser@localhost -p 2222`（密碼：labuser）
2. 執行 `pkaction --verbose --action-id org.freedesktop.packagekit.package-install-untrusted`
3. 觀察到 `allow_active = yes`（正常應為 `auth_admin`）

**Flag 1 截圖**
（貼上 pkaction --verbose 輸出截圖，標示過度寬鬆的 allow_active 值）

**修補建議**
- 將自訂 polkit 規則檔中的 `return polkit.Result.YES` 改為 `return polkit.Result.AUTH_ADMIN_KEEP`
- 或編輯 action XML：將 `allow_active` 由 `yes` 改為 `auth_admin`
- 參見 patched container 的規則檔範例：`/etc/polkit-1/rules.d/10-pack2theroot-lab-hardened.rules`

### 3.2 TOCTOU Race Condition（CVE-2026-41651）

| 欄位 | 內容 |
|------|------|
| **CVE** | [CVE-2026-41651](https://nvd.nist.gov/vuln/detail/CVE-2026-41651) |
| **漏洞位置** | PackageKit `pk-transaction.c`，`InstallFiles()` |
| **漏洞類型** | Time-of-Check-Time-of-Use（TOCTOU / CWE-367）|
| **CVSS 分數** | 8.8（High）— AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H |
| **受影響版本** | PackageKit 1.0.2 – 1.3.4（12 年）|
| **修補版本** | PackageKit 1.3.5（2026-04-22）|

**漏洞描述**

`pk-transaction.c` 存在三個連鎖缺陷：

1. **BUG 1 — State guard 缺失**：`InstallFiles()`（約 line 4036）無條件覆寫 `cached_transaction_flags` 和 `cached_full_paths`，未驗證 transaction 當前的狀態機階段。
2. **BUG 2 — 狀態回退被靜默接受**：`pk_transaction_set_state()`（約 line 876–881）對逆向狀態轉換（backward transition）不報錯，使 flags 已在未授權的情況下被污染。
3. **BUG 3 — Flag 讀取時機錯誤**：`pk_transaction_run()`（約 line 2273–2277）在 dispatch 時才讀取 `cached_transaction_flags`，而非在 authorization 時讀取。

攻擊者利用 GLib event loop 的優先順序保證，對同一個 transaction 發送兩個非同步 D-Bus `InstallFiles()` 呼叫：
1. 第一個帶 `SIMULATE` flag（0x4，繞過 polkit 授權）
2. 第二個立即發送含惡意套件的請求（覆寫 cached flags/paths）

GLib 的優先順序保證兩個 D-Bus 訊息在 idle callback 執行前都被處理完畢——使此攻擊成為**確定性（deterministic）而非機率性（timing race）**。

**攻擊流程**
1. SSH 進入 vulnerable container（`ssh labuser@localhost -p 2222`）
2. 建立含惡意 `%post` scriptlet 的 RPM 套件
3. 透過 `pkcon install-local --allow-untrusted` 安裝
4. `%post` scriptlet 以 root 權限執行，將 `/root/flag.txt` 複製出來
5. 讀取 `/tmp/flag_captured.txt` 確認 root 執行身分

**Flag 2 截圖**
（貼上 `/root/flag.txt` 內容截圖，需包含 `id` 輸出確認為 root）

**修補建議**
- 升級至 PackageKit 1.3.5（commit `76cfb675`）
- state guard 的技術意義：在 `InstallFiles()` 執行前檢查 transaction 狀態是否為 `IDLE`，若非 `IDLE` 則拒絕請求，防止狀態機被並發操作污染

## 四、TOCTOU 防禦實作

### 4.1 Python 模擬結果

**脆弱版本（`transaction_demo.py --vulnerable`）**

```
結果：
  總輪數：1000
  balance 出現負數：993 次
  執行超過一次：   993 次
```

觀察結果：在 1000 輪壓力測試中，高達 **993 次**出現負數餘額，同時有 **993 次**雙重執行。這驗證了經典 TOCTOU race condition：兩個 thread 同時通過 `self.state != self.AUTHORIZED` 檢查後，都執行 `self.balance -= amount`，導致 balance 被扣了兩次。

**安全版本（`transaction_demo.py --safe`）**

```
結果：
  總輪數：1000
  balance 出現負數：0 次
  執行超過一次：   0 次

🏁 FLAG{w12_s4f3_st4t3_m4ch1n3_d3f3ns3}
```

安全版本使用 `threading.Lock()` 將 state 檢查、sleep 後重新驗證、以及扣款操作全部包在同一個 mutex 區塊內，確保這些操作是不可分割的（atomic）。

**Flag 3 截圖**
（貼上壓力測試通過的截圖，需顯示「balance 出現負數：0 次」）

### 4.2 安全實作說明

選擇 **方法 A：`threading.Lock()`**（mutex）作為修復方向。

此方法能防止 TOCTOU 的原因：
1. **原子性（Atomicity）**：`with self.lock:` 確保同一時間只有一個執行緒能進入臨界區段（critical section）
2. **重新驗證（Re-verify）**：`time.sleep(0.001)` 模擬 GLib event loop 的處理延遲後，再次檢查 `self.state != self.AUTHORIZED`——若狀態在 sleep 期間已被其他 thread 改變，則此次執行直接回傳 False
3. **完整覆蓋**：check（state != AUTHORIZED）→ sleep → re-check → use（balance -= amount）全部在同一把鎖的保護下

相較於單純的「sleep 後重新讀取」（仍有微小 race window），Lock 方案提供了最強的保證。

```python
def safe_execute(self, amount: int) -> bool:
    with self.lock:
        if self.state != self.AUTHORIZED:
            return False
        time.sleep(0.001)
        if self.state != self.AUTHORIZED:
            return False
        self.balance -= amount
        self.state = self.COMPLETE
        self.execution_count += 1
        return True
```

## 五、IOC 與偵測

**journalctl 異常訊息**
（貼上 `journalctl -u packagekit | grep "assertion failed"` 的截圖）

**說明**

在 CVE-2026-41651 的完整 TOCTOU 攻擊（透過 D-Bus 直接操作）中，當 packagekitd 因 `cached_transaction_flags` 被污染而觸發內部 assertion 時，系統日誌會出現：

```
assertion failed: (!transaction->priv->emitted_finished)
```

此 assertion failure 是 **PackageKit daemon 崩潰的特徵**，也是攻擊成功的副作用。監控此日誌模式可作為入侵偵測的指標。

在本次 Lab 的 polkit bypass 路徑（透過 `pkcon install-local --allow-untrusted`）中，因為攻擊不涉及 D-Bus race，所以 packagekitd 不會 crash，日誌中不會出現此訊息。

## 七、結論與建議

**整體風險評估**

若此系統部署至生產環境，**任何擁有本地 shell 的攻擊者**（如透過 web shell、SSH 弱密碼、或惡意 insider）都能在 1 分鐘內取得完整的 root 權限。不需要任何特殊權限、不需要記憶體利用技巧、只需要標準的套件管理工具。此漏洞結合 CVSS 8.8 的高分與極低的攻擊複雜度，屬於**必須立即處理的危急漏洞**。

**優先修補順序**
1. **立即升級 PackageKit 至 1.3.5 以上** — 修補狀態機的核心缺陷
2. **稽核所有 polkit action 的 allow_active 設定** — 確認沒有任何 action 設為 `yes`
3. **部署 auditd 監控 PackageKit 操作日誌** — 監控異常的套件安裝請求

**系統性防禦建議**
- **最小權限原則**：定期稽核所有本機使用者的 shell 存取權限，移除不必要的帳號
- **定期稽核 polkit rules**：使用 `pkaction --verbose` 確認每個 action 的授權設定符合安全基線
- **AppArmor / seccomp**：限制 PackageKit daemon 的系統呼叫權限，減少漏洞被利用後的影響範圍
- **auditd / Falco**：部署執行時期監控規則，偵測異常的套件安裝行為（如大量本地套件安裝）
- **網路隔離**：即使此漏洞為本地提權，network segmentation 可降低攻擊者取得本地 shell 的機會
